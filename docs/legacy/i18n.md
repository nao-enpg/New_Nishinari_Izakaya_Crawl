# 言語の切り替えと文言

## 仕組み

- 言語は URL の `?locale=ja|en` で決まる。無ければ ja。
- すべての内部 URL に `?locale=` を付ける（`default_url_options`）。
- 対応言語は ja と en だけ。それ以外を渡すと `I18n::InvalidLocale` で **500**（D-009）。
- 本番は `i18n.fallbacks = true` なので、en に訳が無いと ja の文言を出す。
- `require_login` が `set_locale` より先に動くため、未ログイン時の転送先 URL の言語は、そのリクエストの `?locale=` ではなく、直前に設定された値（既定の ja か、同じスレッドで前に処理したリクエストの言語）になる（推定。D-023）。

## 言語の指定が消える箇所（D-008）

1. ヘッダーのサイト名（`href="/"` 直書き）
2. 店名検索のフォーム（GET フォームはクエリを置き換える）
3. 近い10件のフォーム（同上）
4. 地図のマーカーのクリック（`/izakayas/${id}` 直書き）
5. ログイン後の移動先（`root_path` だが、コールバック時の言語は ja になる）

また、`JP` / `EN` を押すと、検索条件などほかのクエリが消える（`url_for(locale:)` がクエリを引き継がない）。

## 訳の抜け・キーの誤り

| 箇所 | 内容 | 差分台帳 |

## 直書きの文言（訳語にする → D-007）

- 「旅程表に追加しました。」「追加に失敗しました。」「旅程表から削除しました。」（izakaya_plans。英語の画面でも日本語）
- 「Favorite not found」（favorites。日本語の画面でも英語）
- 「Welcome to DEEP OSAKA」（トップの見出し。デザイン上の英語として残すか要確認）
- aria-label「呑みに行く」「呑み計画を立てる」
- alert「Geolocation is not supported by this browser.」
- 画像の alt「Google Logo」「X Logo」「izakaya」
- meta-tags の site・title「西成泥酔旅行」（英語の画面でも日本語。旅程表の詳細の og:title も同じ）
- 問い合わせの placeholder「example@mail.co.jp」
- 言語切り替えの「JP」「EN」

## 日本語だけのもの（要確認）

- 利用規約・プライバシーポリシーの本文
- 店名・タグ名・紹介文（DB のデータ）
- 404 / 422 / 500 のエラーページは英語だけ
