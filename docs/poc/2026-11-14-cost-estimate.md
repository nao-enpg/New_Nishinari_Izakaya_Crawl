# 費用の試算 — 2026-11-14（v0.1）

工程計画 P1-6。単価は公式の料金表で確かめた（下の出典）。アクセス数は、現行サイトの GA4 の実数がまだ無いので、**月の PV を 1,000・10,000・100,000 の3通りで仮に置いた**。GA4 の数字が届いたら差し替える（第6章）。

## 1. 結論

- **費用のほとんどは写真**。現計画（5画面すべてで、表示のたびに Place Photos で取る）では、月 10,000 PV で**約 $470/月**になる。写真以外（Workers・D1・地図・座標の更新）は、ほぼ Workers の基本料金 $5/月だけ。
- 写真の方式で桁が変わる（第3章）。

  | 方式 | 1,000 PV | 10,000 PV | 100,000 PV |
  | --- | --- | --- | --- |
  | 現計画: Place Photos を全5画面で | $41 | $472 | $3,713 |
  | Places UI Kit の Place Details 要素を全5画面で | $0 | $58 | $525 |
  | Place Photos は詳細だけ。カードは自前の写真か代替画像 | $0 | $14 | $203 |
  | 自前の写真だけ（Workers の静的ファイル） | $0 | $0 | $0 |

- **決めてほしいこと（Nao）**: 写真の表示方式（第4章の案 A〜D）と、写真の日次上限（第5章）。どの案でも、カードの見た目が現行と変わるなら差分台帳に載せる。

## 4. 写真の表示方式の案

| 案 | 内容 | 費用 | 規約 | 注意点 |
| --- | --- | --- | --- | --- |
| A. 現計画 | サーバーの取得口で Place Photos を取り、全5画面で出す | 最も高い（上の表） | 適合（写真をキャッシュしない、撮影者を出す） | 取得口が悪用されると課金が増える。日次上限・レート制限・Bot 対策が必須 |
| B. Places UI Kit | カードと詳細に `gmp-place-details-compact`（写真1枚＋撮影者の表示）を置く | 約 1/7〜1/8。無料枠が10倍 | 適合（Google の部品をそのまま使う） | **pre-GA**。見た目の調整は、部品が用意した範囲（表示する項目、向き、明暗の配色など）に限られる（細部は要確認）。ブラウザで描くので SSR されず、読み込み後に高さが変わる見込み。Maps JS の読み込みが要る。ブラウザ用キー（リファラー制限）は抜き出して叩かれうるので、API ごとの日次クォータが要る |
| C. 詳細だけ Google の写真 | カードは自前の写真か代替画像。詳細だけ A か B | 小さい | 適合 | カードの見た目が現行と変わる（差分台帳に載せる） |
| D. 自前の写真だけ | Nao が撮影し、Workers の静的ファイル（または R2）で配る | $0（静的ファイルは無料・無制限） | 対象外（自分の写真） | 撮影の手間。写真の差し替えにデプロイが要る（R2 なら不要）。撮影していない店は代替画像 |

Claude の提案: **D を基本にし、撮影していない店だけ C（詳細だけ Google の写真）**。費用が読めて、取得口の悪用の心配も小さい。B は費用が安いが pre-GA なので、F4 の時点で GA になっていれば改めて比べる。

## 5. 写真の日次上限（案 A・B・C で Google の写真を使う場合）

月の予算に収まる枚数（30日で割った値）。

| 月の予算 | Place Photos | Places UI Kit |
| --- | --- | --- |
| $0（無料枠だけ） | 33枚/日 | 333枚/日 |
| $5 | 57枚/日 | 500枚/日 |
| $10 | 81枚/日 | 667枚/日 |
| $30 | 176枚/日 | 1,333枚/日 |

- Place Photos（サーバーで取る）: アプリ側で D1 に日ごとの件数を数え（1本の SQL で加算して判定）、上限を超えたら代替画像を返す。さらに Google Cloud の API ごとの日次クォータを、上限より少し上に設定する（予算アラートは通知するだけで止めない）。
- Places UI Kit（ブラウザで取る）: アプリ側では正確に数えられないので、Google Cloud の日次クォータで止める。止まったときは要素が表示されないので、代替画像を出す。
- 上限を超えた分は、表示を劣化させても止めない（constitution の案「外部 API が上限に達しても、表示を劣化させてサービスは止めない」）。

## 6. Nao にお願いしたいこと

1. **GA4 の数字**（現行サイトが動いていた最後の12か月）: 月ごとの PV を、ページのパス別（`/izakayas`、`/izakayas/:id`、`/plans`、`/plans/:id`、`/profile`、その他）に。あれば、ユーザー数とモバイルの割合も。
2. **写真の表示方式**（第4章の A〜D）と、**月の予算**（第5章の上限の元になる）。
3. 案 D を選ぶ場合、自分で撮影した写真がどれくらいあるか（店数の目安）。
