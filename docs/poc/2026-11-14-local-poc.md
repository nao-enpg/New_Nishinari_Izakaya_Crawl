| 項目 | 結果 | 根拠 |
| --- | --- | --- |
| a. React Router v8＋`@cloudflare/vite-plugin` の雛形がローカルの workerd で動くか | **OK** | `vite preview` で SSR し、loader から Prisma＋D1 を読めた |
| a. Worker の入口に Cron（scheduled）を同居できるか | **OK** | `workers/app.ts` に `scheduled` を足し、`/cdn-cgi/handler/scheduled?cron=…` で起動して D1 が更新された。ただし `wrangler.jsonc` の `triggers.crons` はまだ無い（F2 で追加） |
| a. サーバー側のバンドルサイズ | **非圧縮 約 4.4MB（gzip 約 1.4MB）** | Prisma の WASM が 3.3MB、JS が 1.0MB。Workers の上限は Free・有料とも**非圧縮で 64MiB**（2026-11 時点）なので十分収まる |
| a. SSR＋Prisma の CPU 時間 | **未計測** | 手元の値は本番と違うので、staging で計測する（参考: `wrangler check startup` の起動時間はローカルで約 56ms） |

| b. 店名の部分一致 | **差あり（対応が必要）** | 英字の大文字・小文字は区別しない（現行の ILIKE と同じ）。ただし Prisma の `contains` は `%` と `_` をエスケープしないので、`%` で検索すると全店を返す（独立検証で再現）。現行の ransack はエスケープし、前後の空白も除く。F4 では自前でエスケープする。全角英字の大文字・小文字は区別する（Q-009） |
| c. D1 の `batch()` は途中で失敗すると巻き戻るか | **OK** | 2文目を失敗させると、1文目の更新も残らなかった。独立検証で、実行時のエラー（主キーの重複、外部キー違反、3文目での失敗）でも巻き戻ることを確認 |
| c. Prisma の配列形式 `$transaction([...])` | **原子性なし** | 2文目が失敗しても、1文目の更新が**残った**。警告が出て、失敗した文のエラーは呼び出し元に返る |

| c. Prisma のネストした書き込み | **原子性なし** | 親と子を一度に作り、子が外部キー違反で失敗すると、**親の行だけが残った**（独立検証で確認） |
| c. 並べ替え（ranked-model 相当）を `batch()` で | **OK** | 位置を振り直す UPDATE を `batch()` でまとめて実行できた |
| c. D1 での外部キーの強制 | **確認** | 子がある親を消すと `FOREIGN KEY constraint failed` になる。独立検証で、`ON DELETE CASCADE` の場合はテーブルの作り直しで子の行が消えることも確認 |
| f. `useFetcher` の楽観的更新 | **OK** | サーバーが 1.5 秒かかる設定でも、ハートは約 0.13 秒で切り替わった。再読み込み後も保たれた |
| f. JavaScript が無効でも動くか | **OK** | フォーム送信だけでお気に入りが登録できた |
| f. ドラッグ＆ドロップのタッチ操作 | **未検証** | 実機（iPhone の Safari、Android の Chrome）で確かめる |

## 分かったこと（計画・CLAUDE.md に反映済み）

1. **パッケージマネージャは pnpm にした**。旧構成（Vitest 4.1＋`@cloudflare/vitest-pool-workers`）では npm 10.9 が `Cannot read properties of null (reading 'edgesOut')` で落ちた。今の構成では npm でも入るが、pnpm に統一する。
2. **Vitest は 5.1 を使える**。`@cloudflare/vitest-pool-workers` は非推奨になり、後継の `@cloudflare/vitest-plugin@1.8.2` が Vitest 5 に対応している。
3. **`npx prisma` は 8.0 RC を取ってくる**。`pnpm exec prisma` を使う。
4. この作業環境では `binaries.prisma.sh` に届かない。`prisma generate` は `PRISMA_SCHEMA_ENGINE_BINARY=/bin/true` をその場で付ければ動く。**付けたまま `prisma migrate diff` を実行すると、何も出力せずに正常終了する**ので、migrate diff は CI か手元の PC で実行する。
5. **Vitest で Prisma の WASM を読むには**、`cloudflareTest` に `wrangler.configPath` を渡す必要があった。
6. テストのたびに D1 が初期化されるわけではない。テストの最初に表を空にする必要があった。
7. **Prisma ではトランザクションも、ネストした書き込みも、原子性が無い**。原子性が必要な処理は `batch()` か1本の SQL で書く。連鎖削除（CASCADE）も使わない。
8. 多言語化は、現行の文言が100件程度で `?locale=` 方式なので、**ライブラリを使わない型付き辞書**が最も単純で安全。Paraglide JS 3 と、`react-i18next@17`＋`i18next@26` を候補として残す。

## 再現の手順（`poc/local` ブランチ）

```sh
pnpm install
PRISMA_SCHEMA_ENGINE_BINARY=/bin/true pnpm exec prisma generate
pnpm exec vitest run                       # b・c・g のテスト
pnpm exec wrangler d1 migrations apply DB --local
pnpm exec wrangler d1 execute DB --local --file scripts/seed-local.sql
pnpm build && pnpm exec vite preview --port 5173
curl "http://localhost:5173/poc/izakayas?tag=1&tag=2"          # a・b
curl "http://localhost:5173/cdn-cgi/handler/scheduled?cron=0+3+*+*+*"   # a（Cron）
```
